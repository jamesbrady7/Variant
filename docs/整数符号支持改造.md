# 整数符号支持改造（Int / UInt 分槽）

> 目标读者：**内网分支维护者**。内网版本基于"所有整型都进 Int（int64）"的旧模型，
> 并且有自己的适配改动；本文给出改动清单、合并策略和验证方法。
>
> 对应公网提交：`18110d6 feat(core)!: 新增 UInt 槽……`
> 原则：**按函数名定位，不要按行号**（内网行号必然不同）。

## 1. 要解决的问题

旧模型只有一个 `Int` 槽（int64）：

- 无符号值超过 `INT64_MAX` 时**构造就抛 `OutOfRange`**，`size_t` / 哈希值 / 外部 ID
  这类数据根本存不进来；
- 即使值不大，存进去也分不清原始是 `int` 还是 `unsigned`。

本次只区分**符号性**，不区分 32/64 位（都按 64 位装）。

## 2. 模型变化

| 项目 | 旧 | 新 |
| --- | --- | --- |
| 槽位 | 7 个内建 + 扩展 | **8 个内建 + 扩展**（新增 `UInt`） |
| 有符号构造 | `Int` | `Int`（不变） |
| 无符号构造 | 转 int64，超范围抛异常 | `UInt`（uint64，完整范围） |
| `get<T>` / `is<T>` | 只认 `Int` | `Int` 与 `UInt` **按范围互读** |
| `asInt()` | 只认 `Int` | `Int` 直接读；`UInt` 能放进 int64 时读，否则 `OutOfRange` |
| `asUInt()` | 无 | 新增；`Int` 非负时读，负数 `OutOfRange` |
| JSON 大正整数 | 退化成 `Double` | 先进 `UInt`，超 uint64 才退 `Double` |
| 二进制 | tag `0x03`（int，zigzag） | 新增 tag **`0x09`**（uint，varint） |
| Python | `int` | `int`（无变化） |
| `sizeof(Variant)` | 40 | **40**（实测不变） |

关键兼容性：

- `Type::UInt` **追加在枚举与存储末尾**，已有类型的数值不变；
- 二进制新 tag 是纯增量：**新代码能读旧数据，旧代码读不了含 0x09 的新数据**；
- `Variant(0u)` 现在是 `UInt`（`isInt()` 为 false），但 `asInt()` / `get<int64_t>()`
  在值放得下时仍然可用——大多数调用点不用改。

## 3. 逐文件改动清单

> 下面每块都给出"旧 → 新"的最小片段。找不到对应代码时，按注释里的函数名/用途搜。

### 3.1 `lib/include/vt/variant.h`

**① Type 枚举**（追加在末尾，不要插在 Int 后面）

```cpp
// 旧
    Extension  ///< 扩展槽（std::any）
};
// 新
    Extension, ///< 扩展槽（std::any）
    UInt       ///< std::uint64_t（追加在末尾，已有类型的数值不变）
};
```

**② 构造函数**

```cpp
// 旧：只有 int64 构造 + 模板 toInt64 收口（越界抛异常）
Variant(std::int64_t v) noexcept : m_storage(v) {}
template <class T, enable_if integral && !bool>
Variant(T v) : Variant(toInt64(v)) {}

// 新：新增 uint64 构造；模板按符号性分派
Variant(std::int64_t v) noexcept : m_storage(v) {}
Variant(std::uint64_t v) noexcept : m_storage(v) {}
template <class T, enable_if integral && !bool>
Variant(T v) : Variant(integerValue(v)) {}
```

私有收口函数（替换 `toInt64`）：

```cpp
template <class T>
static auto integerValue(T value) noexcept
{
    if constexpr (std::is_unsigned_v<T>)
        return static_cast<std::uint64_t>(value);
    else
        return static_cast<std::int64_t>(value);
}
```

**③ 谓词**：`isInt()` 旁边加

```cpp
bool isUInt() const noexcept { return type() == Type::UInt; }
```

**④ `is<T>()` / `get<T>()`**

```cpp
// is<T>：整型判断
return isInt() || isUInt();
// is<T>：浮点判断
return isDouble() || isInt() || isUInt();
```

`get<T>` 的整型分支：`Int` 槽保持原逻辑；**新增 `UInt` 槽分支**：

```cpp
if (isUInt()) {
    const auto u = std::get<std::uint64_t>(m_storage);
    if constexpr (std::is_signed_v<U>) {
        if (u > static_cast<std::uint64_t>(std::numeric_limits<std::int64_t>::max()))
            return std::nullopt;
        const auto v = static_cast<std::int64_t>(u);
        if (v > static_cast<std::int64_t>(std::numeric_limits<U>::max()))
            return std::nullopt;
        return static_cast<U>(v);
    } else {
        if (u > static_cast<std::uint64_t>(std::numeric_limits<U>::max()))
            return std::nullopt;
        return static_cast<U>(u);
    }
}
```

浮点分支补一行：`if (isUInt()) return static_cast<U>(std::get<std::uint64_t>(m_storage));`

**⑤ `asIntOr` 兼容 UInt；新增 `asUInt` / `asUIntOr` 声明与内联实现**（见 `variant.cpp` 同名实现）。

**⑥ Storage**

```cpp
    std::shared_ptr<VariantExt>,      ///< Type::Extension（内部 std::any）
    std::uint64_t                     ///< Type::UInt
>;
```

### 3.2 `lib/src/variant.cpp`

**① 类型名**

```cpp
case Variant::Type::UInt: return "uint";
```

**② `asInt()`**：`Int` 直接返回；`UInt` 越界抛 `OutOfRange`；错误文案改成
"expected int or uint"。

**③ 新增 `asUInt()`**：

```cpp
std::uint64_t Variant::asUInt() const
{
    if (isUInt())
        return std::get<std::uint64_t>(m_storage);
    if (isInt()) {
        const std::int64_t v = std::get<std::int64_t>(m_storage);
        if (v < 0)
            throw VariantError(VariantErrorCode::OutOfRange,
                               "negative value cannot be read as uint");
        return static_cast<std::uint64_t>(v);
    }
    throw VariantError(VariantErrorCode::TypeMismatch,
                       std::string("expected uint or int, got ") + typeName());
}
```

**④ `asDouble()` / `asDoubleOr()`**：补 `if (isUInt()) return static_cast<double>(...)`。

**⑤ `operator==`**：补

```cpp
case Type::UInt: return std::get<std::uint64_t>(m_storage) == std::get<std::uint64_t>(other.m_storage);
```

（保持"不同槽不相等"：`Variant(5) != Variant(5u)`，与 Int/Double 的现有严格性一致。）

### 3.4 `lib/src/json.cpp`

```cpp
if (result.ec != std::errc::result_out_of_range)

if (*start != '-') {
    std::uint64_t unsignedInteger = 0;
    const auto unsignedResult = std::from_chars(start, tokenEnd, unsignedInteger);
    if (unsignedResult.ec == std::errc() && unsignedResult.ptr == tokenEnd) {
        out = Variant(unsignedInteger);
        return true;

}
// 落到后面的 double 解析
```

### 3.6 `lib/include/vt/normalize.h`（值遍历）

**① `ValueSink` 增加事件**（`onInt` 旁边）：

```cpp
virtual void onUInt(std::uint64_t value) = 0;
```

**② `visitValue` 的整型分支**：

```cpp
// 旧：无符号越界抛异常，再统一 onInt
// 新：
if constexpr (std::is_unsigned_v<U>)
    sink.onUInt(static_cast<std::uint64_t>(value));
else
    sink.onInt(static_cast<std::int64_t>(value));
```

**③ `VariantSink`**：

```cpp

    PyErr_Clear();   // 必须清，否则溢出标志污染后面的判断
```

## 4. 怎么带进内网（三种方式，按可行性选）

### 方式 A：Git 补丁（推荐）

公网侧导出：

```bash
git format-patch -1 18110d6 -o /tmp/uint-slot
# 只导出代码、不要文档改动时：
git format-patch -1 18110d6 -- lib binding tests -o /tmp/uint-slot
```

把 `.patch` 拷进内网（U 盘/内网跳板均可），在内网分支上：

```bash
git am --3way /path/0001-*.patch
# 或
git apply --3way /path/0001-*.patch
```

- `--3way` 会在冲突处留下冲突标记并按本文第 3 节人工补；
- 如果内网不是 git 仓库，用 `git apply` 之前先把内网目录 `git init` 建个临时仓，
  或直接按方式 B 手工改。

**冲突热点**（内网改过的概率最高）：

| 文件 | 热点 | 处理 |
| --- | --- | --- |
| `variant.h` | 构造/取值函数区 | 保留内网自己的重载，把 `integerValue`/`isUInt`/`get` 的 UInt 分支补进去 |
| `json.cpp` | `parseNumber` | 内网若改过数字策略，只在"int64 越界"分支插入 uint64 尝试 |
| `binary.cpp` | tag 表 | **先确认 0x09 没被占用**；被占用就换一个未用值，并同步读端 |
| `normalize.h` | 值为旧版（无 Sink） | 只改"无符号越界"那条分支 |
| `variant_python.cpp` | 旧版无 PySink | 在旧的扩展槽转换分支加 UInt → `PyLong_FromUnsignedLongLong` |

### 方式 B：按本文手工改

适合内网结构已明显分叉、`git am` 冲突太多的情况。按第 3 节顺序做，每改完一层就编译：

1. `variant.h` + `variant.cpp` → 编译核心；
2. `json/binary/debug` → 跑序列化回归；
3. `normalize.h` + binding → 跑 Python 回归；
4. 测试断言同步。

### 方式 C：只做"最小兼容"（不推荐，仅应急）

如果不方便改数据模型，可以临时在**应用层**把超过 int64 的无符号值转成字符串或
`std::any(uint64)` 扩展值存。代价：失去 `asUInt`/类型判断/JSON 精度，
且以后迁移到 UInt 槽时还要再洗一遍数据。

## 5. 内网落地后的自检

把下面这段贴进任意一个测试 TU，全部通过再合入：

```cpp
#include "vt/vt.h"
#include <cassert>
#include <limits>

void uintSlotSelfCheck()
{
    const std::uint64_t umax = std::numeric_limits<std::uint64_t>::max();

    // 1) 构造 / 槽位 / 完整范围
    vt::Variant u(umax);
    assert(u.isUInt() && !u.isInt());
    assert(u.asUInt() == umax);

    // 2) 跨槽读取与越界
    assert(!u.get<std::int64_t>().has_value());
    assert(u.get<std::uint64_t>().value_or(0) == umax);
    vt::Variant small = 7;
    assert(small.asUInt() == 7);
    vt::Variant smallU(std::uint64_t(7));
    assert(smallU.asInt() == 7);

    // 3) JSON：大整数不再丢精度
    const vt::Variant fromJson = vt::json::read(vt::json::write(u));
    assert(fromJson.isUInt() && fromJson.asUInt() == umax);
    assert(vt::json::read("18446744073709551616").isDouble());

    // 4) 二进制往返 + 旧数据兼容（旧数据是 tag 0x03，仍应能读）
    const vt::Variant fromBin = vt::binary::read(vt::binary::write(u));
    assert(fromBin.isUInt() && fromBin.asUInt() == umax);

    // 5) 容器遍历
    const auto list = vt::detail::normalizeToVariant(std::vector<unsigned long long>{umax});
    assert(list.asList()[0].isUInt());

    // 6) 布局没变（如果内网对 sizeof 有约束）
    static_assert(sizeof(vt::Variant) == 40, "Variant layout changed");
}
```

回归水位（公网对应提交，含远端并行改动）：`vt_tests` 270、`vt_serial_tests` 1832、
`vt_shared_tests` 33、`vt_plugin_override_test` 31、`py_scripts/demo.py` 52。

## 6. 两个可以自行取舍的设计点

1. **小的无符号值也进 UInt**（本次选择）。好处是类型稳定、`isUInt()` 永远可信；
   代价是依赖 `isInt()` 的旧代码对 `Variant(5u)` 会走到 else 分支。
   如果内网这类代码很多，可以改成"无符号值 ≤ INT64_MAX 时进 Int"——但那就回到
   "类型随值变化"，不推荐。
2. **Int 与 UInt 严格不相等**（本次选择，和 Int vs Double 的既有语义一致）。
   如果内网需要数值相等，改 `operator==` 加跨槽比较，但要先想清楚 `-1` vs `UINT64_MAX`
   的规则。

## 7. 回滚

- 代码回滚：`git revert <commit>` 即可（纯增量槽位，不影响旧路径）。
- **数据风险**：一旦有二进制文件写入了 tag `0x09`，回滚后的旧代码读到会报
  `unknown binary tag`。回滚前确认没有持久化的 UInt 数据，或保留新版本读取端。
- JSON 没有这个问题（旧代码会把大数字读成 Double，精度可能丢，但不会报错）。
