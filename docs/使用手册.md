## 0.1 术语速查

| 术语 | 含义 |
| --- | --- |
| Variant | 运行时承载任意类型的值容器；内部是 variant + 扩展槽。 |
| VariantMap | `string -> Variant` 的哈希表；JSON 里对应 object。 |
| VariantList | `Variant` 的数组；JSON 里对应 array。 |
| 字面键 / 路径 | `"a.b"` 是键；`"a.b"_path` 是路径。见第 1 章。 |
| 扩展槽（extension slot） | Variant 的第 8 个存储槽，内部 `std::any`；用来存没进入内建七槽的 C++ 类型。 |
| codec | 某个 C++ 类型的双向序列化转换器：`T -> 普通 Variant -> T`。 |
| 普通 Variant | 只含 Null/Bool/Int/Double/String/Map/List、不含扩展槽的表示。 |
| 信封（envelope） | JSON 里用三个保留键标记扩展类型的对象：`{"$vt":"1","$type":"类型名","$data":普通表示}`。 |
| plain codec | 内建容器的 codec：表示本身就是数组/对象，JSON 默认直接写出，不加信封。 |
| Auto / EnvelopeAll | `ExtensionPolicy` 的两个值：Auto = plain codec 写普通数据、其余写信封；EnvelopeAll = 所有扩展都写信封。 |
| 类型擦除（type erasure） | Variant 只保留运行时类型信息；JSON 数组 / Python list 本身不携带 C++ 类型，所以读回只能得到 VariantList。 |
| `getAs<T>` | 按目标 C++ 类型，从扩展槽或普通 List/Map 转换回来。 |
| hook | Python 桥接里的转换器；和 codec 是两套独立注册，互不替代。 |

## 1. 五分钟上手（C++）

```cpp
#include "vt/vt.h"
using namespace vt::literals;    // 只为 _path 字面量

vt::Variant root;

// 路径写入：自动建中间节点
root["config.window.width"_path] = 1280;
root["root.subtree_1.subsubtree_1"_path] = vt::VariantList{1, 2, 3};

// 字符串 = 字面键（不是路径）
root["a.b"] = 1;                    // 键 "a.b"

// 读取
int w = root.getAt<int>("config.window.width"_path).value_or(0);
const vt::Variant* p = root.find("root.subtree_1"_path);   // 不抛，缺失 nullptr
root.at("config.window"_path);                              // 缺失/类型冲突抛 VariantError

// 运行时字符串当路径
vt::Path path = vt::Path::parse(runtimeText);
root.getAt<int>(path);
```

### 1.1 访问契约

```text
字符串 -> 字面键
Path   -> 路径
```

| 目的 | 写法 |
| --- | --- |
| 键写入（自动创建） | `v["key"] = value` |
| 键读取（缺失 Null） | `v["key"]`（const 重载返回拷贝） |
| 路径写入 | `v["a.b"_path] = value` |
| 路径读取（指针） | `v.find("a.b"_path)` |
| 路径读取（严格） | `v.at("a.b"_path)` |
| 安全取值 | `v.getAt<T>("a.b"_path)` → `std::optional<T>` |
| 非抛出写入 | `v.set("a.b"_path, value)` → `bool` |

`VariantMap` / `VariantList` 也是同一套方法名：

```cpp
vt::VariantMap m;
m["a.b"] = 1;          // 键
m["a.b"_path] = 2;     // 路径
m.at("a.b");           // 键，缺失抛
m.at("a.b"_path);      // 路径，缺失抛
```

### 1.1.1 字面量与指针输入

```cpp
vt::Variant a = "hello";            // String（拷贝进 std::string）
vt::Variant b = "";                 // String，空串（不是 Null）
const char* p = nullptr;
vt::Variant c = p;                  // Null
vt::Variant d = nullptr;            // Null
vt::Variant e = 'a';                // Int 97（char 是整数，不是字符串）
```

`char*` / `const char*` / `std::string_view` / `std::string` 都进 String；
**空指针**进 Null。不要用 `NULL` 宏（在部分平台展开成 `0`，会变成 Int 0），用 `nullptr`。

`Variant::fromValue` 行为与构造一致；`fromValue(std::string_view)` 会拷贝，
不会在扩展槽里存一个可能悬空的 view。

所有整型都落到 Int 槽（`int64`）。**无符号值超过 `INT64_MAX` 时抛
`VariantError(OutOfRange)`**，不会静默回绕成负数。需要完整 64 位无符号范围时，
把它作为扩展值存：`vt::Variant::fromValue(std::any(std::uint64_t(x)))`。

### 1.2 路径语法

| 写法 | 含义 |
| --- | --- |
| `a.b.c` | 三个键 |
| `a[0].b` | 键 + 下标 + 键 |
| `[0].key` | 列表根：下标 0 下的键 |
| `["a.b"]` | **字面键** `a.b`（点号不再是分隔符） |
| `["c[0]"]` | 字面键 `c[0]` |
| `["a\"b"]` | 键 `a"b`（`\"`、`\\` 转义） |
| `""` | 空路径 = 根自身 |

记住：`[123]` 是下标，`["..."]` 是键，`[abc]` 是语法错误。

### 1.3 只读必须用 const 引用

map/list 是写时复制：

```cpp
const vt::Variant& ro = value;
ro.asMap().size();       // 不 detach
value.asMap().size();    // 非 const：可能克隆整张表
```

扩展类型（如 `std::vector<int>`）同理：只读用 `const` 的 `extensionPtr`。

### 1.4 移动

```cpp
vt::Variant v = std::move(map);   // 移动进去，零元素拷贝
vt::Variant c = map;              // 拷贝（值语义）
```

## 3. Python 使用（不注册自定义类型）

```python
import variant_binding as vb
vb.initTypes()          # 注册示例类型；用到自定义类型前必须调用一次

doc = vb.PyDocument()
assert vb.pyDocSet(doc, "root.items[0]", 10)
assert vb.pyDocGet(doc, "root.items[0]") == 10
assert doc.has("root.items[0]")
print(doc.lastError())
```

### 3.1 Python 侧 API

| API | 作用 |
| --- | --- |
| `vb.initTypes() -> bool` | 注册示例类型（DemoNode / DemoColor / SharedNode），幂等 |
| `vb.PyDocument()` | 文档对象 |
| `vb.pyDocGet(doc, path) -> native` | 按路径读取；缺失返回 `None` |
| `vb.pyDocSet(doc, path, value) -> bool` | 按路径写入；失败返回 `False` |
| `doc.has(path) -> bool` | 路径是否存在 |
| `doc.lastError() -> str` | 最近一次失败原因 |
| `doc.clear()` | 清空文档 |
| `vb.pyEcho(value) -> native` | 整体往返（Python → C++ → Python） |
| `vb.pyDescribe(value) -> str` | JSON 风格调试文本 |
| `vb.canConvertToPython(value) -> bool` | 跨界预检（递归） |

`PyDocument` 的 `get/set` 是模块级函数（为了绕开 shiboken 对 `PyObject*`
参数的限制）。想要 `doc.get(...)` 形式，可以包一层：

```python
class Document:
    def __init__(self):
        self._impl = vb.PyDocument()
    def get(self, path):
        return vb.pyDocGet(self._impl, path)
    def set(self, path, value):
        return vb.pyDocSet(self._impl, path, value)
    def has(self, path):
        return self._impl.has(path)
    def lastError(self):
        return self._impl.lastError()
    def clear(self):
        self._impl.clear()
```

### 3.2 类型映射

| C++ Variant | Python |
| --- | --- |
| Null | `None` |
| bool | `bool` |
| int64 | `int`（超出范围抛 OverflowError） |
| double | `float` |
| string | `str`（UTF-8） |
| map | `dict`（键必须是 str） |
| list | `list`（也接受 tuple） |
| 注册的对象类型 | 同一个 Python wrapper（`is` 保持） |
| 注册的值类型 | 拷贝出来的 Python 对象 |

## 4. 注册自定义类型（重点）

目标：注册一次后，这个类型的对象可以出现在 **VariantMap / VariantList 的任意嵌套层级**，
随整棵树转成 Python `dict/list`，再从 Python 转回 C++，且行为正确。

### 4.1 先选：对象类型还是值类型

| | 对象类型（object-type） | 值类型（value-type） |
| --- | --- | --- |
| Variant 里存什么 | `T*`（指针） | `T`（值） |
| Python 往返后 | **同一个对象**（`is` 为 True） | 拷贝（`is` 为 False） |
| 适用 | 有身份/可变状态的对象 | 小数据/不可变值（颜色、点、范围） |
| 注册函数 | `registerPointerType<T>` | `registerValueType<T>` |
| C++ 要求 | 类可导出、有默认构造更佳 | 可拷贝、**可默认构造** |

还有第三种：需要 C++ 与 Python **共同持有**同一对象时用共享类型
`registerSharedType<T>`（Variant 存 `std::shared_ptr<T>`，Python 仍是 `T`），见 4.8。

### 4.2 完整示例：对象类型 `MyNode`

**第 1 步：定义类（全局命名空间）**

```cpp
// my_types.h
#pragma once
#include <string>

#if defined(_WIN32)
#  if defined(MY_DEMO_EXPORT)
#    define MY_API __declspec(dllexport)
#  else
#    define MY_API __declspec(dllimport)
#  endif
#else
#  define MY_API
#endif

// 注意：shiboken6 的 typesystem 不接受 "ns::Class"（错误 GD60709C2），
// 可绑定类必须放在全局命名空间。
class MY_API MyNode {
public:
    MyNode() = default;
    MyNode(int id, const std::string& name) : m_id(id), m_name(name) {}

    int id() const { return m_id; }
    void setId(int id) { m_id = id; }
    std::string name() const { return m_name; }
    void setName(const std::string& name) { m_name = name; }

private:
    int m_id = 0;
    std::string m_name;
};
```

**第 2 步：加入构建**

- 源文件加入 `demo/CMakeLists.txt` 的 `add_library(variant_demo ...)`；
- 头文件加入 `binding/CMakeLists.txt` 的 `HEADERS`；
- 如果头文件在别的目录，再补 `SHIBOKEN_EXTRA_OPTIONS -I<目录>` 和 `/FI<头文件>`。

**第 3 步：在 typesystem 里声明**

```xml
<!-- binding/variant_bindings.xml -->
<object-type name="MyNode"/>
```

**第 4 步：加入生成的 wrapper 列表**

shiboken 会生成 `mynode_wrapper.cpp`（类名小写 + `_wrapper.cpp`）：

```cmake
set(VARIANT_GEN
    ...
    ${CMAKE_CURRENT_BINARY_DIR}/variant_binding/mynode_wrapper.cpp)
```

**第 5 步：注册**

```cpp
// binding/src/demo_registration.cpp（或你自己的注册函数）
ok = registerPointerType<MyNode>("variant_binding", "MyNode") && ok;
```

第一个参数是模块名（与 `.pyd` 同名），第二个是 shiboken 里的类名。

**第 6 步：重新构建并验证**

```python
import variant_binding as vb
vb.initTypes()

doc = vb.PyDocument()
node = vb.MyNode(7, "alpha")

assert vb.pyDocSet(doc, "nodes.first", node)
back = vb.pyDocGet(doc, "nodes.first")
assert back is node              # 对象身份保持
back.setName("renamed")
assert node.name() == "renamed"  # 同一个 C++ 对象
```

### 4.3 值类型 `MyColor`

类定义同上，但注册用：

```cpp
registerValueType<MyColor>("variant_binding", "MyColor");
```

typesystem：

```xml
<value-type name="MyColor"/>
```

Python 行为：

```python
color = vb.MyColor(10, 20, 30)
vb.pyDocSet(doc, "color", color)

copied = vb.pyDocGet(doc, "color")
assert copied is not color       # 值语义：拷贝
copied.setR(99)
assert color.r() == 10           # 改副本不影响原对象
```

> `registerValueType` 内部用 `T{}` 构造临时对象，因此值类型必须**可默认构造**。

### 4.4 随 VariantMap / List 嵌套往返

注册之后，对象可以出现在任意深度，转换是递归的：

```python
payload = {
    "meta": {"owner": node, "tags": ["a", "b"]},
    "items": [node, 1, None, {"inner": node}],
}

assert vb.canConvertToPython(payload)     # 预检：整棵树都能转
assert vb.pyDocSet(doc, "tree", payload)

back = vb.pyDocGet(doc, "tree")
assert isinstance(back, dict)
assert back["meta"]["owner"] is node
assert back["items"][0] is node
assert back["items"][3]["inner"] is node
assert back["items"][2] is None
```

C++ 侧同样的树可以正常用路径访问：

```cpp
// 取到对象本身（Variant 里存的是 MyNode*）
vt::Variant owner = doc.get(vt::Path::parse("tree.meta.owner"));
MyNode* raw = owner.extensionPtr<MyNode*>();   // 非 const：可能 detach
const MyNode* ro = std::as_const(owner).extensionPtr<MyNode*>();  // 只读用 const

// 取数组
vt::Variant items = doc.get("tree.items");
std::size_t n = items.isList() ? items.asList().size() : 0;
```

### 4.5 生命周期与所有权（必须看）

对象类型在 Variant 里存的是 **裸指针 `T*`**，Variant **不拥有**这个对象。

- Python 创建的 `node` 由 Python 持有所有权；
- 如果 Python 侧丢弃了所有引用，wrapper 被 GC，C++ 对象析构；
- 此时 Variant 里留的是**悬空指针**，再转换会崩。

三种安全做法：

```python
# 1) 在 Python 侧保留引用（最简单）
_keep_alive = []
_keep_alive.append(node)

# 2) 对象由 C++ 创建并持有，Python 只借用
#    （C++ 侧 new 后交给 Python，调用 releaseOwnership 或保持容器持有）

# 3) 本来就想共享生命周期：用 shared 类型注册，见 4.8
```

值类型没有这个问题：进出都是拷贝。

> 三种方案里，只有 4.8 的 `registerSharedType` 能让 **C++ 与 Python 同时安全持有**
> 同一个对象；方案 1 要求 Python 侧永远记得保活，方案 2 要求 C++ 侧活得比 Python 久。

### 4.6 注册时机与失败处理

- `initTypes()` 在 **import 之后、任何转换之前** 调一次；重复调用是幂等的；
- 新增类型后必须重新构建 `.pyd`，并重启 Python 进程；
- 名字冲突（同名被另一种 C++ 类型占用）时注册返回 `false`；
- 未注册类型跨界是**响亮失败**：

```text
TypeError: vt::Variant holds 'MyType' but no Python converter is registered
TypeError: cannot convert Python object of type 'MyType' to vt::Variant
```

- 想提前判断整棵树：

```python
if not vb.canConvertToPython(value):
    raise ValueError("树里有未注册类型")
```

### 4.7 新增类型检查清单

- [ ] 类在**全局命名空间**，并用导出宏导出
- [ ] 值类型可拷贝、可默认构造
- [ ] 源文件加入库目标，头文件加入 `HEADERS`
- [ ] typesystem 加 `<object-type>` / `<value-type>`
- [ ] `VARIANT_GEN` 加 `<小写类名>_wrapper.cpp`
- [ ] `registerPointerType` / `registerValueType` / `registerSharedType` 加一行
- [ ] 重新构建 Release，`initTypes()` 返回 true
- [ ] Python 侧验证：对象身份（对象类型）/ 拷贝语义（值类型）、嵌套 dict/list
- [ ] 共享类型再验三条：C++ 工厂对象进 Variant 后仍可用、Python 对象被收养后身份不变、借用对象被拒绝

### 4.8 共享所有权：`std::shared_ptr<T>`

当对象的生命周期天然由多个持有者共享（图数据库节点、文档对象、缓存项），用
`registerSharedType<T>`：**C++ 侧 Variant 存 `std::shared_ptr<T>`，Python 侧仍然看到普通 `T`**。

```cpp
// 注册（和 4.1 的两个注册函数并列，一行）
ok = registerSharedType<MyNode>("variant_binding", "MyNode") && ok;
```

```cpp
// C++ 写入 / 取回
vt::Variant v = vt::Variant::fromValue(std::make_shared<MyNode>(1, "n"));
auto p = vt::getAs<std::shared_ptr<MyNode>>(v);   // std::optional<shared_ptr<MyNode>>
```

```python
# Python 侧完全不用感知 shared_ptr
node = vb.MyNode(1, "n")          # Python 创建并拥有
vb.pyDocSet(doc, "root.node", node)   # 写入时被“收养”
back = vb.pyDocGet(doc, "root.node")
assert back is node               # 身份保持（不是拷贝）
del node                          # Variant 持有期间对象仍然存活
```

**写入时的三种所有权状态**（按此判定，没有第四种）：

| Python 对象的来源 | 判定依据 | 结果 |
| --- | --- | --- |
| C++ `shared_ptr` 工厂 / 从 Variant 取回 | wrapper 上有 capsule | ✅ 共享同一个控制块 |
| Python 自己构造（绑定构造函数） | 无 capsule、`hasOwnership == true` | ✅ 收养：keep-alive deleter 持有 wrapper 强引用 |
| 从 C++ 借用（`releaseOwnership` 或 C++ 容器持有） | 无 capsule、`hasOwnership == false` | ❌ `TypeError`，拒绝写入 |

第三条是**故意的 fail-fast**：借用对象既不能被收养（会造成双重 delete），
也不该假装共享（C++ 所有者一析构就悬空）。混用所有权机制是这类崩溃的根源，
所以宁可响亮报错，也不降级成裸指针。

内部机制（改转换代码前必读）：

- capsule 名 `vt::shared_owner`，挂在 wrapper 的内部属性 `_vt_shared_owner` 上；
- 收养时 `shared_ptr` 使用 `PythonKeepAliveDeleter`：它**不 delete `T`**，而是持有一份
  wrapper 的强引用；最后一个 `shared_ptr` 释放时 DECREF wrapper，由 Python 真正析构 `T`；
- 同一个 `T*` 只收养一次（`raw -> weak_ptr` 表），多个 Variant 引用同一对象共享一个控制块；
- 已是收养对象时**不会再挂 capsule**，否则 wrapper 与 shared_ptr 互相持有形成引用环；
- C++ `shared_ptr` 路径要求 wrapper **非 owning**，否则所有权冲突，同样报 `TypeError`。

序列化：给 `std::shared_ptr<T>` 注册 codec 后可以进 JSON / 二进制，但编码是**按值**的
（写 `{"id":..., "name":...}` 之类的普通表示）。读回来是**新的** `shared_ptr`，
不保留原来的共享关系与对象身份——这是序列化的固有边界，不是缺陷。

限制：

- keep-alive deleter 只在解释器存活期间 DECREF；已 finalize 时它放弃引用
  （`Py_IsInitialized` 守卫），避免在 finalize 之后碰 Python；
- 收养表按 `T*` 索引，对象析构后留下失效 `weak_ptr`，下次查找时清理；
- 绑定层仍要满足 4.7 的构建要求（全局命名空间、导出宏、wrapper 参与构建）。

演示代码：`demo/demo_types.h` 的 `SharedNode`、`binding/src/shared_bridge.cpp`
的 `pyMakeSharedNode` / `pyBorrowSharedNode`（后者演示必须失败的借用路径）。

## 5. 新增一个 Python 可调用的 C++ 函数

不要用 `vt::Variant` 直接出现在 Python 签名里（shiboken 的签名解析器会 fatal）。
统一走 `PyObject` 直通：

```cpp
// 你的桥接头文件
struct _object* myEcho(struct _object* value);   // 或 PyObject*
```

```cpp
PyObject* myEcho(PyObject* value)
{
    vt::Variant input;
    if (!vpy::fromPython(value, input))
        return nullptr;                 // PyErr 已设置
    return vpy::toPython(myEchoImpl(input));
}
```

XML：

```xml
<add-function signature="myEcho(PyObject)">
    <inject-code class="target" position="beginning">
        return myEcho(%1);
    </inject-code>
</add-function>
```

混合参数（例如 `PyDocument*, const std::string&, PyObject`）时，`PyObject`
那个参数不会生成 `cppArgN`，要用 `%PYARG_3` 取原始 Python 对象。

## 6. 序列化（JSON / 二进制）

> 本章术语（信封、plain codec、类型擦除等）见 0.1。

### 6.1 API

```cpp
#include "vt/vt.h"   // 或 "vt/json.h" / "vt/binary.h"

std::string text = vt::json::write(value);       // 失败抛 SerializeException
vt::Variant back = vt::json::read(text);         // 失败抛

std::string blob = vt::binary::write(value);
vt::Variant fromBlob = vt::binary::read(blob);
```

不抛版本：

```cpp
std::string out;
vt::SerializeError error;
if (!vt::json::tryWrite(value, out, &error)) {
    // error.code / message / offset / line / column
}

vt::Variant value;
if (!vt::json::tryRead(text, value, &error)) { ... }
```

### 6.1.1 流对象

```cpp
std::ostringstream out;
vt::json::writeTo(out, value);                  // bool

std::istringstream in(text);
vt::Variant back;
vt::SerializeError error;
if (!vt::json::readFrom(in, back, &error)) { ... }
```

二进制同名：`vt::binary::writeTo/readFrom`。流接口内部会缓冲整段数据；
`IoError` 表示流读写失败。

### 6.1.2 文件路径

```cpp
vt::json::writeFile("config.json", value);      // 失败抛 SerializeException
vt::Variant v = vt::json::readFile("config.json");

vt::SerializeError error;
if (!vt::json::tryWriteFile("config.json", value, &error)) { ... }
if (!vt::json::tryReadFile("config.json", v, &error)) { ... }
```

二进制同名：`vt::binary::writeFile/readFile`。文件以**二进制模式**打开，
避免 Windows 换行转换；JSON 文件内容仍是 UTF-8 文本。
`tryWriteFile` 会先完成序列化再打开文件，序列化失败不会留下半截文件。

**路径约定**：`std::string` 路径一律按 **UTF-8** 解释（内部走
`std::filesystem::u8path`），所以中文/非 ASCII 文件名可以直接写；
非法 UTF-8 路径返回 `IoError`。注意这与“系统 ANSI 代码页的窄字符串”不同，
从 Win32 API 拿到的 GBK 路径需要先转成 UTF-8；手里已有 `std::filesystem::path`
时传 `p.u8string()`。

**大小边界**：API **没有文件大小上限**，但也没有流式解析——
`readFile` 和 `readFrom(std::istream&)` 都是**整段读入内存**后再解析，
峰值内存 ≈ 文件字节数 + 解析出的 Variant 树（JSON 里每个数组元素是一个
`Variant`，约 40 B）。写侧同理，`writeFile` 先在内存里完成整段序列化再落盘
（换来“失败不留半截文件”）。

所以“能不能读”取决于内存，而不是某个固定阈值：

- 几百 MB 的文件：只要内存够就能读，没有 2 MiB / 2 GiB 的门槛（x64 下
  `size_t`/`streamsize` 都是 64 位）；
- 千万级数值：逐元素进 Variant 会很吃内存（1000 万 int ≈ 400 MB+），
  应存成 `std::vector<int>` 扩展槽或紧凑二进制，而不是 JSON 数组；
- 真正超大（GB 级）：在应用层切分（多个文件/多个路径段）是目前唯一的路，
  本库不提供流式解析器。

二进制还有**单值**上限（不是文件上限）：`BinaryReadOptions::maxStringBytes`
默认 256 MiB、`maxElements` 默认 1600 万，超了报 `BadLength`；JSON 只有
`maxDepth`（默认 256），没有单值长度/元素数上限。

写出选项 `vt::JsonWriteOptions`：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `pretty` | false | 缩进输出 |
| `sortKeys` | true | map 按键排序，输出稳定 |
| `extensions` | `Auto` | 扩展策略：`Auto` / `EnvelopeAll` / `Flatten` / `Reject` |
| `nonFinite` | `Error` | NaN/Inf：`Error` 报错，`Null` 写成 null |
| `maxDepth` | 256 | 最大嵌套深度 |

读入选项 `vt::JsonReadOptions`：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `maxDepth` | 256 | 最大嵌套深度 |
| `detectExtensions` | true | 是否识别 `$vt/$type/$data` 信封 |

### 6.2 JSON 写出规则

| Variant | JSON |
| --- | --- |
| Null | `null` |
| Bool | `true` / `false` |
| Int | 整数（`int64` 全范围） |
| Double | 数字；整值补 `.0`（`1.0`） |
| String | UTF-8 字符串，控制字符转义 |
| Map | object（默认按键排序） |
| List | array |
| 用户扩展类型 | 默认信封：`{"$vt":"1","$type":"Name","$data":...}` |
| 内建容器扩展 | 默认 plain：直接写 `[...]` / `{...}` |

基础例子：

```cpp
vt::json::write(vt::Variant());                       // null
vt::json::write(vt::Variant(true));                   // true
vt::json::write(vt::Variant(42));                     // 42
vt::json::write(vt::Variant(1.0));                    // 1.0
vt::json::write(vt::Variant(1.5));                    // 1.5
vt::json::write(vt::Variant(std::string("a\"b\n")));  // "a\"b\n"
```

容器：

```cpp
vt::Variant map = vt::Variant(vt::VariantMap{{"b", 2}, {"a", 1}});
vt::json::write(map);        // {"a":1,"b":2}   （键已排序）

vt::Variant list = vt::Variant(vt::VariantList{1, "x", true});
vt::json::write(list);       // [1,"x",true]
```

`pretty`：

```cpp
vt::JsonWriteOptions opt;
opt.pretty = true;
vt::json::write(vt::Variant(vt::VariantMap{{"a", 1}}), opt);

// {
//   "a": 1
// }
```

NaN / Inf：

```cpp
vt::json::write(vt::Variant(std::nan("")));   // 抛 UnsupportedValue

vt::JsonWriteOptions opt;
opt.nonFinite = vt::NonFinitePolicy::Null;
vt::json::write(vt::Variant(std::nan("")), opt);   // null（类型丢失）
```

用户扩展（`Point2` 已注册 codec）：

```cpp
vt::Variant p = vt::Variant::fromValue(Point2{1, 2});
vt::json::write(p);
// {"$data":{"x":1,"y":2},"$type":"Point2","$vt":"1"}
```

内建容器默认 plain：

```cpp
vt::json::write(vt::Variant::fromValue(std::vector<int>{1, 2, 3}));
// [1,2,3]

vt::json::write(vt::Variant::fromValue(
    std::unordered_map<int, int>{{3, 4}, {1, 2}}));
// {"1":2,"3":4}
```

`EnvelopeAll` 时也写信封：

```cpp
vt::JsonWriteOptions opt;
opt.extensions = vt::ExtensionPolicy::EnvelopeAll;
vt::json::write(vt::Variant::fromValue(std::vector<int>{1, 2, 3}), opt);
// {"$data":[1,2,3],"$type":"std::vector<int>","$vt":"1"}
```

### 6.3 JSON 读入规则

| JSON | Variant |
| --- | --- |
| `null` | Null |
| `true` / `false` | Bool |
| 整数且落在 `int64` 范围 | Int |
| 带 `.` 或 `e` 的数字 | Double（`1.0` 也是 Double） |
| 超出 `int64` 的整数 | Double（精度可能损失） |
| 字符串 | String |
| array | **VariantList** |
| object | **VariantMap**（键必须是字符串） |
| `$vt/$type/$data` 对象 | 查 codec 还原扩展；未知类型报 `UnknownType` |

例子：

```cpp
vt::json::read("1").isInt();                         // true
vt::json::read("1.0").isDouble();                    // true
vt::json::read("9223372036854775808").isDouble();    // true（超出 int64）
vt::json::read("[1,2,3]").isList();                  // true
vt::json::read("{\"a\":1}").isMap();                 // true
vt::json::read("\"\\uD83D\\uDE00\"").asString();     // "😀"
```

信封：

```cpp
vt::Variant p = vt::json::read(
    R"({"$vt":"1","$type":"Point2","$data":{"x":1,"y":2}})");
p.isExtension();                 // true（前提：Point2 已注册 codec）
auto point = vt::getAs<Point2>(p);
```

关闭信封识别：

```cpp
vt::JsonReadOptions opt;
opt.detectExtensions = false;
vt::Variant plain = vt::json::read(text, opt);   // 得到普通 map
```

重复键：**后者覆盖前者**

```cpp
vt::json::read("{\"a\":1,\"a\":2}").at("a").asInt();   // 2
```

严格解析（都会报错）：

| 输入 | 错误 |
| --- | --- |
| `""` | `UnexpectedEnd` |
| `"01"` | `InvalidNumber` |
| `"+1"` | `Syntax` |
| `".5"` | `Syntax` |
| `"1."` | `InvalidNumber` |
| `"[1,]"` | `Syntax` |
| `"{\"a\":1,}"` | `Syntax` |
| `"\"\\uD800\""` | `InvalidUtf8`（孤立代理） |
| 非法 UTF-8 字节 | `InvalidUtf8` |
| `"1 x"` | `TrailingData` |
| 300 层嵌套 `[` | `DepthExceeded` |

不支持：注释、尾随逗号、前导零、`+1`、`.5`、NaN/Inf 字面量、根值后的多余字符。

### 6.4 扩展类型与策略

先注册 codec：

```cpp
struct Point2 { int x = 0; int y = 0; };

vt::registerValueCodec<Point2>(
    "Point2",
    [](const Point2& p) {
        return vt::VariantMap{{"x", p.x}, {"y", p.y}};
    },
    [](const vt::Variant& plain, Point2& out) {
        auto x = plain.getAt<int>("x");
        auto y = plain.getAt<int>("y");
        if (!x || !y) return false;
        out = Point2{*x, *y};
        return true;
    });
```

`ExtensionPolicy` 的行为：

| 策略 | 用户扩展（Point2） | 内建容器（plain codec） |
| --- | --- | --- |
| `Auto`（默认） | `{"$vt":"1","$type":"Point2","$data":...}` | plain（`[1,2,3]`） |
| `EnvelopeAll` | 信封 | 信封 |
| `Flatten` | 只写 `$data`（`{"x":1,"y":2}`） | plain |
| `Reject` | **报错** `UnsupportedValue` | plain |

`Flatten` 读回：

```cpp
vt::JsonWriteOptions opt;
opt.extensions = vt::ExtensionPolicy::Flatten;
const std::string flat = vt::json::write(p, opt);   // {"x":1,"y":2}
vt::json::read(flat).isMap();                       // true，类型信息丢失
```

未注册 codec：

- 写出扩展 → `UnknownType`；
- 读入未知 `$type` → `UnknownType`；
- **不会**静默变成 list/map（除非显式 `Flatten`）。

`$vt`、`$type`、`$data` 是保留键；业务 map 里要使用它们时，读侧可设
`detectExtensions=false`，或者换一种数据表示。

#### 类型演化（加字段 / 删字段 / 改语义）

字段级兼容**全部在 codec 的 `encode`/`decode` 里**，库不做迁移。三层各管各的：

- `$vt` 是**信封格式**版本，不要拿它表达类型变化；
- `$type` 是类型身份，**保持稳定**；改名等于旧数据 `UnknownType`；
- `$data` 里的字段由你的 `decode` 解释。

```cpp
// 加字段 z：encode 写最新，decode 给旧数据默认值
[](const vt::Variant& plain, Point& out) {
    auto x = plain.getAt<int>("x");
    auto y = plain.getAt<int>("y");
    auto z = plain.getAt<int>("z");
    if (!x || !y) return false;            // 必需字段缺失 -> UnsupportedValue
    out = Point{*x, *y, z.value_or(0)};    // 新字段默认值
    return true;
}
```

三条纪律：

1. **每个字段明确"缺失=默认值"还是"缺失=不合法"**；可选字段给默认值（向后兼容），
   必需字段 `return false`（响亮失败）。
2. 需要区分语义时，把版本写进 **`$data`**：`{"schema":2,"x":..,"z":..}`；
   ⚠ 不要往信封里加第 4 个键——当前识别要求恰好 3 个键，多一个就退回普通 map。
3. 不兼容的变化（字段含义被复用、类型改变）用**新类型名**断代，旧 codec 保留；
   注意 `CodecRegistry` 按 `typeid(T)` 唯一，一个 C++ 类型只能有一个协议名。

回归：把每种历史格式的 JSON 样本留在测试里，`decode` 改动后必须仍能读旧样本。

### 6.5 内建容器

| C++ 类型 | 存储 | JSON 默认 | C++ -> Python |
| --- | --- | --- | --- |
| `std::vector<Variant>` | 原生 List | array | list |
| `std::unordered_map<std::string, Variant>` | 原生 Map | object | dict |
| `std::vector<int>` | 扩展槽（紧凑） | `[1,2,3]` | `list[int]` |
| `std::vector<std::string>` | 扩展槽 | array | `list[str]` |
| `std::unordered_map<std::string, std::string>` | 扩展槽 | object | `dict[str,str]` |
| `std::unordered_map<int, int>` | 扩展槽（键转十进制字符串） | object | `dict[int,int]` |

```cpp
vt::Variant v = vt::Variant::fromValue(std::vector<int>{1, 2, 3});

// 扩展槽或普通 List 都能按目标类型读回
auto a = vt::getAs<std::vector<int>>(v);
auto b = vt::getAs<std::vector<int>>(vt::json::read("[1,2,3]"));

vt::Variant m = vt::Variant::fromValue(std::unordered_map<int, int>{{1, 2}});
auto c = vt::getAs<std::unordered_map<int, int>>(m);
auto d = vt::getAs<std::unordered_map<int, int>>(
    vt::Variant(vt::VariantMap{{"1", 2}}));   // 字符串键也能解析
```

为什么默认 plain：内建容器的表示本身就是数组/对象，外部系统能直接消费。
代价是读回时不知道它原本是 `vector<int>` 还是 `vector<string>`，需要 `getAs<T>`。

Python 侧（`initTypes()` 之后）：

```python
sample = vb.makeBuiltinSample()
sample["ints"]       # [1, 2, 3]
sample["strings"]    # ["a", "b"]
sample["strmap"]     # {"x": "y"}
sample["intmap"]     # {1: 2, 3: 4}

vb.sumInts([4, 5, 6])               # 15
vb.intMapSize({1: 2, 3: 4})         # 2
```

Python 的 `list`/`dict` 回到 C++ 时只能变成 `VariantList`/`VariantMap`（无类型信息），
需要原容器类型时用 `getAs<T>`；`dict[int,int]` 的键在 Variant 内是十进制字符串。

**覆盖内建 codec**：内建 codec 是懒注册（第一次序列化时 `call_once`）。想换掉某个
内建类型的表示，必须在**第一次 `write/read/writeFile/...` 之前**注册自己的 codec；
注册过的类型不会被内建实现覆盖，一旦序列化发生过就来不及了。

### 6.6 往返完整性矩阵

| 值 | 默认写出 | 读回 | 完全无损？ |
| --- | --- | --- | --- |
| Null / Bool / Int / Double / String | 直接 | 同类型 | ✅（NaN/Inf 除外） |
| VariantMap / VariantList | object / array | 同类型 | ✅（map 顺序丢失） |
| 内建容器 | plain 数组/对象 | List / Map | ❌ 类型丢失；`getAs<T>` 可恢复 |
| 内建容器 + `EnvelopeAll` | `$type` 信封 | 扩展类型 | ✅ |
| 用户扩展（`Auto`/`EnvelopeAll`） | `$type` 信封 | 扩展类型 | ✅（codec 必须仍注册） |
| 用户扩展 + Flatten | `$data` | 普通类型 | ❌ |
| 用户扩展 + Reject | 报错 | — | — |
| 二进制 | 始终带类型名 | 扩展类型 | ✅（内建容器也是） |

因此：

```cpp
vt::Variant v = vt::Variant::fromValue(std::vector<int>{1, 2, 3});
vt::json::read(vt::json::write(v)).isList();   // true，不是扩展
vt::binary::read(vt::binary::write(v)).isExtension();  // true
```

### 6.7 数字、字符串、容器边界

数字：

- `1` ↔ Int，`1.0` ↔ Double；Double 整值写出时补 `.0`；
- `-0.0` 保持 Double；
- 超过 `int64` 的整数读成 Double；
- NaN/Inf 默认写出报错；`NonFinitePolicy::Null` 写成 `null`（读回是 Null）。

字符串：

- 必须是合法 UTF-8，否则 `InvalidUtf8`；
- 支持 `\" \\ \/ \b \f \n \r \t \uXXXX`；
- 代理对正确组合，孤立代理报错；
- `\u0000` 可以往返。

容器：

- JSON object 的键只能是字符串；
- `map<int,int>` 的键写成十进制字符串，`getAs` 解析回来；
- `sortKeys=true` 只影响输出顺序，读回仍是 `unordered_map`；
- 重复键后者覆盖前者。

### 6.8 二进制格式

```
'V' 'T' 'B' 0x01           // magic + version

0x00 null
0x01 false
0x02 true
0x03 int64   + zigzag varint
0x04 double  + 8 字节 IEEE754 小端
0x05 string  + varint 长度 + UTF-8
0x06 list    + varint 数量 + value*
0x07 map     + varint 数量 + (string key + value)*
0x08 扩展    + 类型名 + 编码后的 value
```

例子：

```text
null        -> 56 54 42 01 00
int 42      -> 56 54 42 01 03 54      // zigzag(42) = 84 = 0x54
"hi"        -> 56 54 42 01 05 02 68 69
```

二进制**始终带扩展类型名**，所以内建容器和用户类型都能精确恢复；
读取端会校验 magic/version/长度/深度，并有 `maxStringBytes`、`maxElements` 上限。

### 6.9 错误模型

`vt::SerializeError`：

```cpp
struct SerializeError {
    SerializeErrorCode code;
    std::string message;
    std::size_t offset;   // 字节偏移
    int line, column;     // 1-based（JSON）
};
```

| 码 | 含义 |
| --- | --- |
| `Syntax` | 语法错误 |
| `UnexpectedEnd` | 数据提前结束 |
| `InvalidUtf8` | 非法 UTF-8 |
| `InvalidNumber` | 数字格式/范围错误 |
| `DepthExceeded` | 嵌套过深 |
| `UnknownType` | 扩展类型没有注册 codec |
| `UnsupportedValue` | NaN/Inf 等不能表示的值 |
| `BadLength` | 长度字段非法 |
| `VersionMismatch` | 版本不匹配：JSON 信封 `$vt` 或二进制头 |
| `TrailingData` | 根值后有多余数据 |
| `EncodeFailed` | codec 编码失败 |
| `IoError` | 流/文件读写失败 |

`write/read` 抛 `SerializeException`（`what()` 带结构化信息）；`tryWrite/tryRead`
返回 `bool` 并填 `SerializeError`。

### 6.10 与 Python 的关系

- C++ 的 JSON 序列化**暂未暴露**给 Python；
- Python 侧看到的是原生 `None/bool/int/float/str/list/dict` 和注册类型的 wrapper；
- 纯数据可以直接交给 Python 的 `json.dumps/loads`；wrapper 对象不行；
- **codec 与 hook 是两套注册**：注册 codec 只影响 C++ 序列化，注册 hook 只影响 Python 转换；
- 需要 Python 侧直接读写 C++ 序列化格式时，可以再加 `pyDocToJson/pyDocFromJson`。

### 6.11 完整示例

```cpp
struct Point2 { int x = 0; int y = 0; };
vt::registerValueCodec<Point2>(...);   // 见 6.4

vt::Variant root = vt::VariantMap{
    {"name", "demo"},
    {"ids", vt::Variant::fromValue(std::vector<int>{1, 2, 3})},
    {"point", vt::Variant::fromValue(Point2{1, 2})},
    {"tags", vt::VariantList{"a", "b"}},
};

std::string text = vt::json::write(root);
// {"ids":[1,2,3],"name":"demo","point":{"$data":{"x":1,"y":2},"$type":"Point2","$vt":"1"},"tags":["a","b"]}

vt::Variant back = vt::json::read(text);
back.at("ids").isList();              // true（类型丢了）
back.at("point").isExtension();       // true（信封恢复了 Point2）

auto ids = vt::getAs<std::vector<int>>(back.at("ids"));   // 需要时再转回
auto point = vt::getAs<Point2>(back.at("point"));

// 想让 ids 也精确恢复：
vt::JsonWriteOptions typed;
typed.extensions = vt::ExtensionPolicy::EnvelopeAll;
vt::Variant typedBack = vt::json::read(vt::json::write(root, typed));
typedBack.at("ids").isExtension();    // true

// 内部持久化优先用二进制：类型精确、体积小
vt::Variant binBack = vt::binary::read(vt::binary::write(root));
binBack.at("ids").isExtension();      // true
```

如果要把整棵树给外部系统（Python/JS/服务），用默认 plain 或
`ExtensionPolicy::Reject`；内部保存/恢复用二进制或 `EnvelopeAll`。

## 7. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `TypeError: ... no Python converter is registered` | 类型没注册，或注册在转换之后 | 调 `initTypes()` / 检查注册行 |
| `TypeError: cannot convert Python object ...` | Python 对象类型未注册 | 同上；检查模块名/类名 |
| `ImportError: DLL load failed` | 缺 `python3.dll` / `shiboken6.abi3.dll` / `variant_core.dll` / `variant_demo.dll` | 与 `.pyd` 放同目录或加 PATH |
| `LNK2001: __imp__Py_RefTotal` | 用 Debug 构建绑定 | 用 Release / RelWithDebInfo |
| `GD60709C2: Nesting types by specifying '::'` | typesystem 写了 `ns::Class` | 类放全局命名空间 |
| `Fatal: seterror_argument did not receive a result` | 签名里出现 `vt.Variant` | 改用 `PyObject` 直通 |
| `copyToPython: 没有重载函数接受 0 个参数` | 自动绑定方法用了 `PyObject*` 形参/返回 | 改成自由函数 + add-function |
| 对象往返后 `is` 为 False | 注册成了值类型 | 对象类型用 `registerPointerType` |
| 取回对象后崩溃 | Python 对象被 GC，Variant 持有悬空指针 | 保留 Python 引用 / 改 C++ 拥有 |
| `TypeError: ... borrowed from C++; create it via a shared factory` | 借用对象写入共享类型 Variant | 用 C++ `shared_ptr` 工厂创建，或让 Python 独占该对象 |
| `TypeError: ... is Python-owned but has no shared owner` | C++ 侧把 Python 拥有的 wrapper 当 `shared_ptr` 用 | 走 `registerSharedType` 的工厂/收养路径，别手工混用所有权 |
| `VariantError: [OutOfRange]` | 无符号整型超过 `INT64_MAX` | 缩小范围，或存 `std::any(uint64_t)` 扩展值 |
| `SerializeError: VersionMismatch` | JSON 信封 `$vt` 或二进制头版本不被支持 | 确认版本；旧数据需重新序列化 |
| `IoError: cannot open '<中文名>'` | 路径不是 UTF-8（例如 Win32 API 给的 GBK） | 先转 UTF-8，或传 `filesystem::path::u8string()` |
| `pyDocSet` 返回 False | 路径类型冲突/越界/值不可转换 | 读 `doc.lastError()` |

## 8. 速查

### C++

```cpp
vt::Variant v;
v["key"] = 1;                       // 键
v["a.b"_path] = 2;                  // 路径
v.at("a.b"_path);                   // 严格
v.find("a.b"_path);                 // 指针
v.getAt<int>("a.b"_path);           // optional
v.set("a.b"_path, 3);               // bool
v.isMap(); v.isList(); v.isExtension();

// 运行时路径
vt::Path p = vt::Path::parse(text);
vt::Path q; vt::Path::tryParse(text, q, &err);

// 扩展值（密集数组）
vt::Variant arr = vt::Variant::fromValue(std::move(vectorInt));
const auto& ro = arr;
const std::vector<int>* data = ro.extensionPtr<std::vector<int>>();

// 共享所有权（Variant 存 shared_ptr<T>）
vt::Variant sv = vt::Variant::fromValue(std::make_shared<MyNode>(1, "n"));
auto sp = vt::getAs<std::shared_ptr<MyNode>>(sv);
```

### Python

```python
import variant_binding as vb
vb.initTypes()

doc = vb.PyDocument()
vb.pyDocSet(doc, "a.b", value)      # 路径写入
vb.pyDocGet(doc, "a.b")             # 路径读取
doc.has("a.b"); doc.lastError(); doc.clear()

vb.pyEcho(value)                    # 往返
vb.pyDescribe(value)                # 调试文本
vb.canConvertToPython(value)        # 预检

# 自定义类型（对象）
node = vb.MyNode(1, "n")
vb.pyDocSet(doc, "nodes.first", node)
assert vb.pyDocGet(doc, "nodes.first") is node

# 共享所有权：C++ 侧 shared_ptr<T>，Python 侧仍是 T
shared = vb.pyMakeSharedNode(1, "shared")
vb.pyDocSet(doc, "nodes.shared", shared)
assert vb.pyDocGet(doc, "nodes.shared") is shared
```
