## 目标

main 只保留必要的 Python 接口：

- 真实 C++ 签名：`vt::Variant` / `vt::VariantMap` / 标准容器；
- 类型注册入口 `initTypes()`；
- 转换核心 `vpy::fromPython/toPython`（conversion-rule 依赖，不能删）。

## 分支

- `legacy/pyobject-api`：旧 PyObject 门面（`PyDocument`、`pyDocGet/pyDocSet/pyEcho/...`）原样封存；
- `experiment/variant-converter` → 未来 main：新接口。

## main 删除

- 绑定类 `PyDocument`；
- `pyDocGet`、`pyDocSet`、`pyEcho`、`pyDescribe`、`pyMakeSharedNode`、`pyBorrowSharedNode`、`canConvertToPython`；
- 仅服务旧门面的桥接代码；`vpy` 转换核心保留。

## main 保留并改为真实签名

- `makeSample()/makeBuiltinSample()` → `vt::Variant`；
- `sumInts(const std::vector<int>&)`、`intMapSize(const std::unordered_map<int,int>&)`；
- 已实现：`echo/echoMap/echoList/echoVector/echoUnorderedMap`。

## 虚函数

- `PluginBase` 增加 `virtual vt::VariantMap transform(const vt::VariantMap&) const`；
- Python 子类重写，C++ 调用，验证参数/返回值双向转换。

## 后续：容器自动递归（2026-11-01，分支 `feature/container-traits`）

真实签名解决了"函数签名里的容器"，但扩展槽里的容器（`Variant::fromValue` 存的）
仍靠逐类型 hook：`vector<vector<int>>` 无法转换、嵌套容器无法序列化。

已完成：

- `vt/container_traits.h`：容器形状公开定制点（Sequence/Map/Pair，默认 Leaf）；
- `vt/normalize.h`：`normalizeToVariant` / `denormalizeFromVariant` 递归，
  `getAs<T>` 改为 traits 驱动，支持任意嵌套；
- `Variant::fromValue<T>` 首次见到容器类型时登记归一化函数 + plain codec；
- `vpy::toPython` 扩展槽回退：hook → 归一化 → TypeError；
- 删除 `binding/core/container_hooks.*`（逐类型 hook 不再需要）；
- 值遍历拆成"一份编译期递归 + 两个 Sink"（`docs/值遍历改造计划.md`）：
  `VariantSink`（JSON/二进制，键按文本）与 `PySink`（Python，键保留真实类型）；
- 非字符串映射键：序列化侧写十进制文本（JSON 规范要求字符串成员名），
  **Python 侧保留 int / 对象键**；反向 dict -> C++ 仍字符串化，由 `getAs<T>` 解析。

未变：容器仍整体存扩展槽（紧凑）；用户 codec 仍优先。

## 共享测试的持有方式

`PyDocument` 删除后，测试使用三个仅测试用的真实签名函数：

```cpp
void holdPayload(const vt::VariantMap&);
vt::VariantMap heldPayload();
void releasePayload();
```

由 C++ 静态 `VariantMap` 持有，验证“Python / C++ 两侧都不持有则对象释放”。
